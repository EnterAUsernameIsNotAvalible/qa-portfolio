# API Testing

Manual API-тестування Restful-Booker API через Postman. Повний CRUD + негативні кейси.

**[restful_booker_crud.json](./restful_booker_crud.json)** — Postman-колекція (Collection v2.1, імпортується напряму).

## Що покриває

**CRUD-цикл:**
POST /auth → POST /booking → GET → PUT → PATCH → DELETE → GET (перевірка видалення)

**Негативні кейси — знайдені баги:**

| Запит | Очікував | Отримав | Суть |
|---|---|---|---|
| POST /booking з порожнім/неповним body | 400 | **500** | API не валідує вхідні дані, падає замість чемної відмови |
| PATCH /booking з порожнім body | 400 | **200** | "Успіх" без жодної реальної зміни — вводить в оману |
| POST /auth з невалідними credentials | 401 | **200** | Автентифікація не блокує неправильний логін/пароль |
| PATCH з невалідним токеном | 403 | **200** | Авторизація не перевіряє токен на цьому шляху |
| DELETE неіснуючого id | 404 | **500** | Немає перевірки існування ресурсу перед видаленням |

5 розбіжностей between очікуваною і фактичною поведінкою API, кожна задокументована окремим запитом з описом у назві.

**Стек:** Postman, REST (Restful-Booker sandbox API).
